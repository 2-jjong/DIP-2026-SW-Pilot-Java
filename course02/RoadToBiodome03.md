## 1. 시간 복잡도의 정의와 필요성

### 1.1 시간 복잡도란?
**시간 복잡도**(Time Complexity)는 입력값의 크기 N이 증가함에 따라 알고리즘이 실행되는 데 걸리는 **연산 횟수의 증가 비율**을 나타내는 척도입니다. 실제 물리적 시간(초/밀리초)은 하드웨어 성능이나 실행 환경에 따라 변하지만, 시간 복잡도는 알고리즘 자체의 논리적 효율성을 객관적으로 평가할 수 있게 해줍니다.

### 1.2 시간 복잡도 분석의 필요성
1. **대용량 데이터 처리**: 입력 데이터가 커질 때 알고리즘이 현실적인 시간 내에 처리 가능한지 미리 판단할 수 있습니다.
2. **자원 및 비용 절감**: 효율적인 알고리즘은 서버의 CPU 및 메모리 사용량을 줄여 성능 저하와 운영 비용을 최소화합니다.
3. **병목 지점 파악**: 코드 내에서 성능 저하를 일으키는 구간을 정밀하게 타격하여 개선할 수 있습니다.

## 2. Big O 표기법의 개념과 상황별 예시

### 2.1 Big O 표기법이란?
Big O 표기법(Big-O Notation)은 알고리즘의 **최악의 경우**(Worst-Case) 성능 상한선을 표현하는 수학적 표기법입니다. 상수항이나 최고차항 미만의 낮은 차수 항은 무시하고, 데이터 크기 N이 매우 커질 때의 주도적인 성장률(Growth Rate)만을 표현합니다.

### 2.2 대표적인 Big O 단계별 예시

| Big O | 명칭 | 예시 알고리즘 | 입력 N=1000 시 연산 횟수 |
| :--- | :--- | :--- | :--- |
| O(1) | 상수 시간 | 배열 인덱스 접근, 스택 push/pop | 1회 |
| O(log N) | 로그 시간 | 이진 탐색 | 약 10회 |
| O(N) | 선형 시간 | 리스트 1회 순회, 회문 검사 | 1,000회 |
| O(N log N) | 선형 로그 시간 | 퀵 정렬, 병합 정렬 | 약 10,000회 |
| O(N²) | 이차 시간 | 중첩 반복문 (이중 for문), 버블 정렬 | 1,000,000회 |
| O(2ᴺ) | 지수 시간 | 피보나치 수열 재귀 호출 | 10³⁰⁰회 이상 (불가능) |

## 3. 문제01 코드의 시간 복잡도 분석

### 3.1 문제01 알고리즘 연산 과정 (`RoadToBiodome01.java`)
`RoadToBiodome01.java`는 입력받은 숫자 리스트 중에서 **단 1번만 등장하는 숫자**를 찾는 프로그램입니다. (단, `HashMap` / `HashSet` 사용 금지)

```java
// 1. 입력 리스트 파싱: O(N)
for (String numberStr : numberStrs) {
    int num = Integer.parseInt(numberStr);
    numbers.add(num);
}

// 2. 1번만 등장하는 숫자 탐색: O(N²)
for (int num : numbers) { // N번 반복
    if (countFrequency(numbers, num) == 1) { // countFrequency 메서드 내부에서 N번 순회
        singleNumber = num;
        break;
    }
}
```

### 3.2 시간 복잡도 계산
- 리스트 길이 = N
- 외부 루프: `numbers` 리스트를 1개씩 순회 $\rightarrow$ N회
- 내부 메서드 `countFrequency(numbers, num)`: 리스트 전체를 1회 순회하여 등장 횟수 카운팅 $\rightarrow$ N회
- **총 연산 횟수**: N × N = N²
- **시간 복잡도**: **O(N²)**

## 4. 문제02 코드의 시간 복잡도 분석

### 4.1 문제02 알고리즘 연산 과정 (`RoadToBiodome02.java`)
`RoadToBiodome02.java`는 스택(Stack)의 LIFO 원리를 이용하여 입력받은 문자열을 역순으로 암호화하고, 회문(Palindrome) 여부를 검사하는 프로그램입니다. (단, `java.util.Stack`, `StringBuilder` 사용 금지)

```java
// 1. 회문(Palindrome) 검사: O(N)
public static boolean isPalindrome(String str) {
    int left = 0, right = str.length() - 1;
    while (left < right) {
        if (str.charAt(left) != str.charAt(right)) return false;
        left++; right--;
    }
    return true;
}

// 2. 스택 Push 연산: O(N)
for (int i = 0; i < input.length(); i++) {
    push(input.charAt(i)); // 각 push는 O(1)
}

// 3. 스택 Pop 연산 및 문자열 재구성: O(N)
while (!isEmpty()) {
    reversedChars[idx++] = pop(); // 각 pop은 O(1)
}
```

### 4.2 시간 복잡도 계산
- 문자열 길이 = N
- 회문 검사: N/2회 비교 $\rightarrow$ O(N)
- 스택 Push: N번 연산 $\rightarrow$ O(N)
- 스택 Pop: N번 연산 $\rightarrow$ O(N)
- **총 연산 횟수**: N/2 + N + N = 2.5N
- **시간 복잡도**: **O(N)**

## 5. 병목 현상 분석 및 최적화 방안

### 5.1 문제01 병목 현상 분석 및 최적화
- **병목 구간**: `main` 함수에서 숫자를 1개 확인할 때마다 `countFrequency()` 함수를 호출해 리스트 전체를 다시 훑는 중첩 탐색 구간.
- **원인**: `HashMap`을 사용할 수 없는 제약조건에서 중첩 루프(O(N²))를 사용하여 탐색 시간이 급격히 증가함.
- **최적화 방안**:
  1. 문제 조건상 숫자의 범위가 0 이상 1000 이하로 제한되어 있으므로, 크기 1001의 **카운팅 배열**을 선언하여 단 1회 순회(O(N))로 빈도수를 기록.
  2. 만약 입력 숫자의 범위가 제한되지 않은 경우에는 리스트를 **정렬**(O(N log N))한 후 이웃한 요소만 비교하는 1회 순회(O(N)) 방식으로 개선 가능.

### 5.2 문제02 성능 분석 및 최적화
- **성능 상태**: 이미 O(N) 선형 시간에 동작하므로 시간 복잡도 면에서는 최적 수준입니다.
- **미세 최적화 방안**:
  - 기존: 스택의 초기 용량을 100으로 시작하여 부족할 때마다 `System.arraycopy`로 2배씩 확장(O(N) 배열 재할당 동적 확장).
  - 개선: `stack = new char[input.length()]`로 처음에 딱 필요한 크기만큼 직접 동적 할당하여 메모리 오버헤드 및 배열 복사 시간 절약.

## 6. 보너스 과제: 코드 최적화 및 Big O 비교

### 6.1 문제01 최적화 적용 및 비교 (RoadToBiodome01)

#### [최적화 적용 방식: 카운팅 배열 활용]
문제 요구사항에 명시된 숫자의 범위(0 이상 1000 이하)를 활용하여 O(N) 시간 복잡도로 개선합니다.

```java
// O(N) 최적화 코드 적용
int[] frequency = new int[1001];

// 1차 순회: 카운팅 배열에 등장 횟수 기록 (O(N))
for (int num : numbers) {
    frequency[num]++;
}

// 2차 순회: 등장 횟수가 1인 숫자 탐색 (O(N))
int singleNumber = -1;
for (int num : numbers) {
    if (frequency[num] == 1) {
        singleNumber = num;
        break;
    }
}
```

#### [Big O 비교표 - 문제01]
| 구분 | 기존 코드 | 최적화 코드 |
| :--- | :--- | :--- |
| **시간 복잡도** | **O(N²)** | **O(N)** |
| **N = 100,000 연산 수** | 약 10,000,000,000 회 | 약 200,000 회 |
| **개선 결과** | 데이터가 커질 때 실행 불가 수준 | 입력 크기에 비례하여 즉시 완료 |
